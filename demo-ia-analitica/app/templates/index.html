Cómo funciona

    
Todo corre dentro del clúster OpenShift, sin enviar datos fuera:

    
    
      
  1. Pregunta en español → el modelo de lenguaje {{ modelo }} (servido por Ollama en CPU, en su propio pod) la traduce a SQL usando el esquema de las tablas.
    2. 
      
  2. La consulta se valida (solo lectura) y se ejecuta en DuckDB; si falla, el modelo la corrige con el error (hasta 3 intentos).
    3. 
      
  3. El modelo resume el resultado con las cifras clave y una recomendación; la aplicación elige el gráfico.
    4. 
      
  4. Predicción de fuga: un modelo de gradient boosting (scikit-learn) se entrena con el histórico al iniciar; su probabilidad queda como columna riesgo_fuga y también se puede preguntar por ella.
    5. 
    

    
Datos 100 % sintéticos de una telco chilena (noviembre 2025 a octubre 2026). En un proyecto real se conectan al data lake o al data warehouse del cliente, y el modelo se puede servir con Red Hat OpenShift AI (vLLM, GPU).

          fecha_alta, fuga, fecha_baja, riesgo_fuga

recargas: recarga_id, fecha, cliente_id, region, canal, monto
